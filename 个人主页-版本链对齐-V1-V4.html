一、为什么要对齐

课程大纲按阶段编号（Stage 1 = V1 … Stage 4 = V4），你仓库里用的是内部小版本（V0 → V1.0 … V1.7 → V2.0）。两套编号混在一起，老师按大纲核对时会直接问："V2、V3、V4 在哪？"

本文件把 56 个 Git 提交归到 4 个阶段，并在本地打了 4 个 tag，任何一个阶段都能一键检出快照。

三、三处还没对齐（必须补，不然会被扣分）

1. 页脚版本号是 V2.0，不是 V4

index.html 第 592 行页脚徽章写的是 V2.0。老师点开链接看到 V2.0，大纲却要求 V4，视觉上就对不上。 → 改成 V4.0（或 V4 · First Month），改完要提交并推送才会更新线上。

2. Stage 3 的反馈证据：桌面上一张都没有

大纲明确要"至少 3 位不同的人 + 3–5 条含义不同的反馈"，且要是截图或记录。 现状：screenshots/ 只有 4 张 Stage 1 的图（V0 深色版、6 Demo 总览、V1 中文、V1 英文），没有任何反馈截图。 → 反馈数据只在你的 Supabase Dashboard 里，得你自己登录导出（表格截图即可）。

3. Stage 2 的 before/after 对比图缺

只有 V0 与 V1 的对比。V1.1（8 板块）、V1.3（数字分身）、V1.4（双机械臂）这些真正的"多轮迭代"没有前后对比图。 → 可以检出旧 tag 截一张、跟现在对比。
